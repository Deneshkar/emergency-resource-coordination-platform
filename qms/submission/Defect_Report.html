ERCP defect and retest report

Three recorded application defects are fixed and retested; BUG-03 was repaired on 5 October. The Windows sandbox interruption is an environment issue, not an application defect.

BUG-01 Public registration grants privileged roles

Severity
Critical
Priority
P1
Status
Fixed and retested
Description
An anonymous caller could register as Admin or Coordinator and receive a valid role-bearing JWT.
Steps
POST /api/auth/register with a unique email, valid password and role Admin or Coordinator.
Expected
400 Bad Request; public accounts restricted to Citizen or Volunteer.
Actual
Before fix both role variants returned 201 Created.
Cause
Registration DTO explicitly allowed privileged roles; the public controller had no role restriction.
Fix
Restrict DTO roles and explicitly reject privileged roles in the public registration action. Trusted test setup provisions a coordinator before logging in.
Evidence
evidence/security-before/security-before.trx: SEC01, two failed cases. evidence/final/backend/backend.trx: SEC01, two passes. evidence/final/live-api.xml: SEC04, two passes.
Retest
Both public privileged roles rejected; ordinary registration and existing authentication tests remain passing.

BUG-02 Low privilege users can modify dispatches

Severity
High
Priority
P1
Status
Fixed and retested
Description
Any authenticated Citizen or Volunteer could create a dispatch. Mutation routes lacked a coordinator/admin authorization requirement.
Steps
Register Citizen or Volunteer, use returned JWT, POST /api/dispatches with incidentId 1 and priority High.
Expected
403 Forbidden for Citizen and Volunteer; coordinator/admin mutation routes remain available.
Actual
Before fix both role variants returned 201 Created.
Cause
Class-level Authorize required authentication only; mutation actions did not specify allowed roles.
Fix
Add Coordinator/Admin authorization to create, status, task create/update/delete and allocation-proposal actions.
Evidence
evidence/security-before/security-before.trx: SEC02, two failures. evidence/final/backend/backend.trx: SEC02 passes. evidence/final/live-api.xml: SEC05 covers seven forbidden actions, and E2E01 verifies authorized completion.
Retest
Citizen/Volunteer dispatch creation rejected; Citizen mutations and validation rejected; coordinator workflow succeeds.

BUG-03 Sequential PostgreSQL migrations create Shelters twice

Severity
High
Priority
P2
Status
Fixed and retested
Description
The original clean migration installation failed. The repaired migration chain now matches the current model schema and supports the tested rollback/upgrade paths.
Steps
Create a separate empty database; run dotnet ef database update with its explicit connection string. Migrations progress until AddAffectedCountToIncidents.
Expected
Migrations apply sequentially without duplicate relations.
Actual
Before: PostgreSQL 42P07, relation Shelters already exists. After: clean schema comparison, rollback/data-preservation and repeated-update tests pass.
Cause
Overlapping table/index creation and incorrect rollback ownership; the model snapshot also contained Users, ValidationAudits and six planner fields without corresponding migration operations.
Fix
Removed duplicate table/index creation, corrected both rollback methods, altered existing shelter foreign keys to match the snapshot, and added CompleteAuthenticationAndPlanningSchema for the missing tables and planner fields.
Evidence
evidence/migration-fix/before/migration-before.trx; evidence/migration-fix/retest/migration-retest.trx; evidence/final/migrations.log; evidence/migration-fix/model-consistency.log; QmsMigrationTests.cs.
Retest
Four regression tests failed before and passed after. The originally failed isolated database upgraded through eight migrations. Backend 95/95 and live HTTP 17/17 pass. Shared/startup-created databases were not automatically adopted.

Other observed limitations

The demo-user endpoint exposes development credentials; production hardening is outside the completed fixes. React lint reports 4 warnings and the production build reports a bundle over 500 kB. The team updated MailKit from 4.7.1.1 to 4.18.1; the 6 October build does not report the earlier NU1902 warning. This is not a complete dependency security audit. Backend coverage is reported from the current Coverlet XML in the PDF, including executed migration/generated model code; the line rate does not imply equivalent business-logic coverage.
